# vTSFM presentation figures

Each figure is available as a vector PDF for the paper and a high-resolution PNG for slides. The November 25 experiments use the same A100 and name the serving revision for each comparison. Earlier figures keep their original device, workload and baseline.

For the presentation, start with the cost of serving an individual forecast, then introduce concurrent arrivals to show when requests can share a model call. Next compare two ways to reduce execution overhead, TimesFM CUDA graph replay and Toto whole-forecast compilation. Close with Moirai to show why faster kernels and finer scheduling still need independent numerical checks on the actual workload.

| [Toto compilation](07-toto-compile-a100.pdf) · [PNG](07-toto-compile-a100.png) | Eager, guarded compile and whole-forecast compile at `6ddddef` on top of `2e13348`. The same two MetroPT input geometries, one or four outstanding clients, six fresh servers and 2,400 completed HTTP requests. The x-axis gives series per request × observations per series, then client count. Initial specialization ran before timing. On two whole-compile points, one additional graph was observed across warmup and timing combined. The measured MetroPT windows passed native checks. A separate five-signal check found a numerical limit on Chiller 6 condenser flow. At B5/C512/H96, 69 of 4,320 eager values and 110 of 4,320 whole-compile values exceeded the native tolerance. Whole compilation introduced 71 distinct failures on this signal. The speedups describe repeated shapes; the adapter remains experimental. | [Timing and memory measurements](data/toto-compile-a100.json) · [Numerical qualification](data/toto-qualification-a100.json) |
| [Moirai attention by forecast horizon](08-moirai-attention-a100.pdf) · [PNG](08-moirai-attention-a100.png) | Both horizons use the same B8/C7168 inputs, created by cyclically extending the prepared MetroPT timeline with a separate offset for each row, on `2e13348`, one server slot. H96 pooled p95 over 200 requests per arm, with independent numerical checks before and after every timing run. At H1024, fused attention exceeded the native tolerance on one series, beginning in block 10. The upstream arm passed all 73,728 values. The right panel shows the failed values per block. | [Timings and error distribution](data/moirai-attention-a100.json) |
| [Moirai block scheduling](09-moirai-block-scheduling.pdf) · [PNG](09-moirai-block-scheduling.png) | Four slots on `bbf77ea`. The saturated burst sends B2/C512/H1024 every millisecond. The mixed burst sends 16 requests every 250 ms at horizons 128, 129, 513 and 1,024. The scheduler preserves each request’s native row grouping. All 800 timed requests passed transport and identity checks. All 160 separate concurrent warmups passed native parity. | [Per-order timings, memory and parity](data/moirai-blocks-a100.json) |
| [Toto direct CUDA graph replay](13-toto-direct-graph.pdf) · [PNG](13-toto-direct-graph.png) | B1/C2048/H96, serialized in-process calls. Both unmodified paths failed capture at a tensor-to-host scale check. A diagnostic change kept tensor scaling on the GPU. Equal input copies, output clones and synchronization were timed for ordinary calls and graph replay; fresh-input and retained-output checks passed. The probe has no HTTP endpoint. | [Timing, capture costs and precision qualification](data/toto-qualification-a100.json) |

The `data/` directory contains the November 25 measurements. [measurements.json](measurements.json) contains the earlier values and source links. From this directory, run `python render.py` for the earlier figures and `python current.py` for the November 25 figures using Python and Matplotlib. The IEEE template can include a vector figure with `\includegraphics[width=\linewidth]{figures/02-timesfm-cuda-graphs.pdf}`.
